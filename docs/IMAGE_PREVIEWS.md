# Private photo previews

Photos appear directly in conversations, with rounded image corners and no surrounding bubble, border, filename or caption. Files shows a bare thumbnail with optional sender/date metadata. Filenames remain available to assistive technology and original downloads. Tap a thumbnail to open a larger image, retry a failed preview, download the unchanged original, or delete your own upload. Images previously uploaded as ordinary files are recognized by filename and included in the Images category. The quick sharing composer also shows the chosen image before sending.

`GET /api/attachments/{id}/preview?size=thumb|full&format=jpeg|webp` returns a data URI and dimensions through the authenticated JSON API. JPEG is the default for existing/native clients; browsers request WebP. Every request checks verification, session, chat membership and whether the recipient was actually sent the attachment, including cache hits. Session and attachment access are checked again after rendering. Responses are not stored by the HTTP cache or service worker; the client does not persist previews in browser storage.

The server reads private object bytes and renders only JPEG, PNG, WebP, GIF and BMP. SVG and unsupported/corrupt formats show a download fallback. Preview generation corrects orientation and strips metadata. WebP preserves transparency; JPEG flattens it onto a neutral background. Animated images use their first frame. Original downloads preserve all original bytes and animation.

Thumbnails have a maximum edge of 512 pixels and enlarged previews 1600 pixels. WebP byte caps are 48 KiB for thumbnails and 320 KiB for enlarged previews; JPEG retains 96/480 KiB for compatibility. These caps exclude base64/JSON overhead and do not imply a fixed compression ratio for every photo. Decoding accepts at most 32 million pixels for JPEG and 16 million for other formats, with a 16000-pixel dimension cap. One render runs at a time, with a 60-second in-memory cache bounded to 4 MiB and 128 entries, keyed by attachment, size and output format. Authorized cache hits bypass the rendering queue. Browser thumbnails load near the visible area; larger previews load only when opened. Larger or unsupported originals remain downloadable.

Verification covers actual JPEG/WebP decoding, alpha preservation, orientation, metadata removal, format-specific size limits, compatibility, unsigned/nonmember/unshared access, cached access after membership loss, verification loss, logout and deletion. Browser acceptance uploads JPEG bytes, decodes WebP chat/Files previews, verifies the absence of the surrounding card and visible filename, retries an enlarged preview and verifies that the original download is unchanged. Synthetic browser fixtures do not create real accounts or send email.
