# Appearance, profile photos, invitations and sharing

Appearance defaults to the device's local clock: light from 07:00, dark from 19:00. You → Appearance offers custom start times, separate day/night palettes, always-light, always-dark and device appearance. The app checks its clock while open and when returning to the foreground, including after timezone changes. Preferences are local to each device. Legacy palette choices are retained in the corresponding day/night slot. There are 15 palettes and four optional backgrounds: quiet, dots, garden and orbits. Decorations appear in chats and welcome screens, with an Appearance preview.

Onboarding and You → Edit profile offer photo selection, replacement and removal. A verified, current-account-only endpoint accepts JPEG, PNG or WebP up to 2 MiB and 16 megapixels, re-encodes a 256px square JPEG and drops source metadata. Only the normalized small image is retained with the profile; original files and GPS/EXIF are not saved. Profile photos use the existing contact-authorized profile responses. Updating a photo does not complete onboarding. Photos work independently of R2 file storage.

Invite someone creates a link without requiring the recipient's email. An optional email restricts redemption to that address. Links are single-use, expire after seven days and retain the inviter relationship; recipients must verify their own email. Only a token hash is stored. The browser link carries its token in the fragment, so it is not sent in the initial HTTP request; login fills the invitation field and removes the fragment from browser history. An interrupted pre-registration reload requires reopening the invitation link. Links are only created, never emailed automatically. The designated branch alias now opens without a Vercel account through an alias-specific exception; KUKU sign-in remains required.

The + button opens readable quick actions on an ordinary tap: new message, file upload, photo sharing, invitation and shared space. Files includes visible upload/photo actions. Both lead to a recipient picker and real binary upload (25 MiB maximum), followed by a durable queued attachment message. Failed uploads retain the selection and show an error. File bytes go directly to the authenticated API; JSON account/profile requests use the uncached same-origin proxy.

**Deployment gate:** Private Vercel Blob is now supported alongside R2. Store creation was rejected by the connected Vercel API (403), so provider activation and real chat-file acceptance still require the owner account step documented in PRIVATE_FILE_SHARING.md. Profile photos and invitations do not have that dependency. Native Android/iOS picker/crop behavior and signed APK acceptance still need physical-device testing.

The bird mark appears in the Home header and onboarding. Deterministic generation produces native app, splash, PWA and favicon assets; generated derivatives are also committed for clean-checkout visibility. Web export explicitly writes versioned favicon links, Apple touch icon and manifest registration into the actual single-page HTML.

Verification covers schedule boundaries and modes, validation, invitation fragments, single-use/expired/email-bound invitations, concurrent redemption, photo authorization/normalization/metadata removal, and a synthetic browser journey including picker uploads, saved appearance, fragment entry and real request bytes. Browser tests use synthetic accounts and mocked providers; they do not send email or prove live R2/device delivery.
