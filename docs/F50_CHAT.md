# F50 chat usefulness simulations — 28 November 2026

Ten synthetic scenarios, C01–C10. These are controlled state/component checks using fixture messages, not ten physical-device sessions. The root checkpoint records exact-source cloud/browser evidence separately.

| ID | Everyday scenario | Result | Executed evidence |
|---|---|---|---|
| C01 | A message changes elsewhere while I am editing; I try Save again before reviewing it. | FIXED: Save stays disabled, its handler refuses a queued press, and review retains my draft and advances the expected revision. | New unit `conflicted edit confirmation waits for deliberate review and keeps the draft`. Browser journey now asserts disabled Save after the real mock-HTTP 409; cloud execution pending root integration. |
| C02 | A message changes while I am removing it; I press Remove again without reviewing. | FIXED: confirmation stays disabled until deliberate review; a queued handler invocation cannot submit. | New unit `conflicted removal confirmation cannot resubmit before latest-version review`. |
| C03 | Search returns the same full page after Load more. | FIXED: deduplicated results remain and the endless no-op Load more disappears. | New unit `search stops repeated full pages rather than offering an endless no-op Load more`. Browser fixture also injects a repeated full page and asserts 20 unique results plus no remaining control; cloud execution pending. |
| C04 | A full search page contains only removed or another conversation's messages. | FIXED: all rows are excluded and pagination stops instead of displaying a stranded Load more that cannot run with no rows. | New unit `a search page containing only foreign or removed rows never strands its Load more control`. |
| C05 | Search pages overlap near the 100-result limit and include an older revision. | FIXED: unique rows determine remaining capacity; the latest revision is preserved instead of overwritten. | New unit `overlapping search pages keep newer revisions and use unique results for the 100-message budget`. |
| C06 | The final search page overlaps and would exceed the result budget. | PASS: retain server order, show at most 100 unique messages, end pagination. | New unit `search keeps server ordering while bounding a final overlapping page to 100 unique messages`. |
| C07 | I receive mixed text, punctuation, web links and unsafe URL schemes. | PASS: text is preserved; valid HTTP(S)/www links normalize; script/data/file/credential URLs stay inert. | Existing units `mixed message links preserve every character and exclude surrounding punctuation` and `unsafe schemes, embedded credentials, controls and malformed addresses stay inert`, re-executed. |
| C08 | I tap a web link, then right-click it for message actions. | PASS: real safe anchor navigation does not also open the message sheet; context-menu requests actions. | Existing units `web links have real safe anchors and do not trigger the message action handler` and `right-clicking a link opens message options without a second browser context menu`, re-executed. | C09 | Clipboard permission fails, then succeeds, or a late copy finishes after changing accounts/panels. | PASS: no false success; a deliberate retry recovers; stale account/panel feedback is ignored. | Existing units `copy permission failure never claims success and a deliberate retry can recover` and `stale account actions and late clipboard results cannot affect a different message panel`, re-executed. |
| C10 | Reconnect occurs during an existing reconciliation, including a failed first pass/account switch. | PASS: coalesce one latest-state pass; preserve history on transient failure; do not retry into another account. | Existing units `a recovery request arriving during reconciliation gets its own latest-state pass`, `a newer recovery request survives a failed first reconciliation without clearing history`, and `a recovery request is not retried into a different account after a failed pass`, re-executed. |
